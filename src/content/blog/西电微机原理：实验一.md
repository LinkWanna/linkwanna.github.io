## 软中断简介

软中断，即软件中断，是一种通过软件指令主动触发的中断机制，允许程序在运行过程中请求操作系统提供特定的服务。这是[维基百科](https://zh.wikipedia.org/wiki/%E4%B8%AD%E6%96%B7)对软中断的定义。

为什么我们需要软中断呢？一般来说，在一块芯片上，往往有多个应用程序同时运行，这些程序都需要访问底层的硬件资源，那么如果每个程序都直接操作硬件，就会导致资源冲突和安全问题。比如大家都想要向中断发送 `Hello World`，如果两个应用一起竞争，那么最后的输出可能是这样的：`HeWollo rorld`，即两个应用相互覆盖**寄存器**需要输出的字符，导致输出混乱。

为了解决这个问题，操作系统引入了软中断机制，通过软中断机制允许程序通过调用操作系统提供的接口来间接访问硬件资源，对于上面的情况，操作系统会负责协调各个应用程序的输出请求，确保输出的顺序和完整性。有了操作系统这个中间的管理层，我们就能够始终保证正确输出两个 `Hello World` 了。

在 x86 架构中，软中断通常通过 `INT` 指令来实现，后跟一个中断号（Interrupt Number），用于指定所请求的服务类型。由此，我们就可以像调用函数一样调用操作系统提供的服务。只不过设置参数和获取返回值都是通过寄存器来完成的。

## 第一小题

**输出 Hello World！**。有了上面的基础知识，我们就可以开始哼哧哼哧地写实验代码了，当然，别忘了[参考文档](https://www.ctyme.com/intr/int-21.htm)呀。第一小题的任务是输出 `Hello World!` 字符串到屏幕上。我们拆分一下这个任务：

1. **准备字符串**：在数据段中定义一个以 `$` 结尾的字符串。
2. **设置寄存器**：将字符串的地址加载到 `DX` 寄存器中，并将 `AH` 寄存器设置为 `09h`，表示调用 DOS 功能 09h（显示字符串）。
3. **调用中断**：使用 `INT 21h` 指令触发软中断，调用 DOS 的字符串显示功能。

```asm
.model small
.stack 100h

.data
msg     db      'Hello World!' ,'$'

.code
start:
    mov     ax, @data
    mov     ds, ax          ; 初始化数据段

    mov     dx, offset msg  ; DS:DX -> "$" 结尾字串
    mov     ah, 09h         ; DOS 功能：显示字串
    int     21h
end start
```

### Q&A 环节
Q: 为什么字符串要以 `$` 结尾？

A: 在 DOS 中，字符串显示功能要求字符串以 `$` 结尾，以便知道字符串的结束位置。如果没有这个结尾符号，DOS 将无法确定字符串的长度，可能会导致显示错误或内存访问违规。这是 DOS 的自己的规定，它以 `$` 作为字符串结束的标志。像 C 中也有自己的规定，使用的是 `\0` 作为结尾符号。

Q: 开头的两条指令是做什么的？而且为什么不直接 `mov ds, @data`？ 

A: 这两条指令用于初始化数据段寄存器 `DS`。这样就保证了后续实验 DX 进行访存时，使用的是 `@data` 段的地址空间。当然不能直接 `mov ds, @data`，是因为 `mov` 指令不支持直接将段名加载到段寄存器中，必须先通过通用寄存器（这里是 `AX`）进行中转。

## 第二小题

**获取用户输入的姓名和学号并一并输出**。和上面一样，我们先拆分任务：

1. **获取用户输入的 name**：定义一个缓冲区用于存放用户输入的姓名，然后使用 DOS 功能 0Ah 来获取用户输入。
2. **获取用户输入的 sno**：同上
3. **回显 name 和 sno**：使用 DOS 功能 09h 来显示用户输入的姓名和学号。

```asm
.model small
.stack 100h

.data
sname   db      'sname: ' ,'$'
sno     db      'sno: ' ,'$'
crlf    db      13, 10, '$'

; 为用户输入分配内存
name_input db 20          ; byte 0: 最大输入长度
           db ?           ; byte 1: 实际输入长度
           db 20 dup(0)   ; byte 3: 输入缓冲区

sno_input  db 20          ; byte 0: 最大输入长度
           db ?           ; byte 1: 实际输入长度
           db 20 dup(0)   ; byte 3: 输入缓冲区

; 换行
newline MACRO
    mov     dx, offset crlf     ; 换行
    mov     ah, 09h             ; DOS 功能：输出字符
    int     21h
ENDM

; 输出字符串
putstr MACRO str
    lea     dx, offset str      ; DS:DX -> 字符串
    mov     ah, 09h             ; DOS 功能：输出字符
    int     21h
ENDM

; 获取字符串输入
getstr MACRO buffer
    lea     dx, offset buffer   ; DS:DX -> 输入缓冲区
    mov     ah, 0Ah             ; DOS 功能：获取输入字符串
    int     21h
ENDM

; 为用户输入的结尾添加 $
pushend MACRO buffer
    mov     cl, buffer+1            ; CL = 用户输入的字符数
    mov     ch, 0                   ; CX = 长度
    lea     si, buffer+2            ; SI 指向第一个字符
    add     si, cx                  ; SI 跳过 CX 个字符
    mov     byte ptr [si], '$'      ; 把 '$' 放在最后一个字符之后
ENDM

.code
start:
    ; 初始化数据段
    mov     ax, @data       
    mov     ds, ax          

    ; 1. 获取用户输入的 name
    putstr sname
    getstr name_input
    pushend name_input
    newline

    ; 2. 获取用户输入的 sno
    putstr sno
    getstr sno_input
    pushend sno_input
    newline

    ; 3 回显 name 和 sno
    putstr name_input+2
    newline
    putstr sno_input+2
    
    ; 带返回码 0 结束
    mov     ah, 4Ch         
    xor     al, al
    int     21h
end start
```

第二题的代码相较于第一题复杂了不少，我们主要是通过宏定义将重复的代码块封装起来，不然 `start` 内的代码将难以阅读。宏定义的使用方式和函数类似，只不过它是在编译阶段进行文本替换，而不是在运行时调用。

### 宏的解释

什么是宏？在 C 里面我们经常会用 `#define` 来定义宏，`masm` 的汇编语言中的宏定义方式略有不同，但本质上都是一种预处理指令，用于在编译时进行文本替换。通过这种替换的机制，它们允许我们定义一段代码块，并在需要的地方插入这段代码，从而避免重复编写相同的代码，提高代码的可读性和维护性。

```asm
getstr MACRO buffer
    lea     dx, offset buffer   ; DS:DX -> 输入缓冲区
    mov     ah, 0Ah             ; DOS 功能：获取输入字符串
    int     21h
ENDM
```

譬如上面的 `getstr` 宏定义了一个获取用户输入字符串的代码块，它接受一个参数 `buffer`，表示输入缓冲区的地址。在宏定义中，我们使用 `buffer` 来引用传入的参数。当我们在代码中调用 `getstr name_input` 时，编译器会将宏体中的 `buffer` 原封不动地替换为 `name_input`，从而生成相应的汇编代码。

但是，宏定义并不是函数调用，它们没有参数传递和返回值的概念，所有的替换都是在编译阶段完成的。这会导致一些潜在的问题，比如是宏展开后可能会引入重复代码，极大地增加代码体积。

### Q&A 环节

Q: 为什么 `name_input` 的定义看起来那么奇怪？

A: 这是因为 DOS 功能 0Ah（获取输入字符串）要求输入缓冲区的格式必须是这样的，所以并没有什么特别的原因，只是 DOS 规定的格式而已：
- 第一个字节：表示缓冲区的最大长度（包括结尾符号）
- 第二个字节：表示实际输入的长度
- 第三个字节及之后：是输入的字符数据

Q: `pushend` 宏是做什么的？

A: `pushend` 宏的作用是为用户输入的字符串添加 `$` 结尾符号，以便后续使用 DOS 功能 09h（显示字符串）它通过读取输入长度，然后在输入的最后一个字符之后添加 `$` 符号来实现这一点。这样能够正确识别字符串的结束位置。

Q: `crlf` 是什么？

A: `crlf` 是一个字符串，包含两个字符：回车（`\r`，ASCII 码 13）和换行（`\n`，ASCII 码 10），用于在输出时实现换行效果。在 DOS 中，输出字符串时需要手动添加换行符，否则所有输出会连在一行显示。

## 第三小题

**输入一个字符，输出其 ASCII 码的十六进制或十进制表示**。我们已经解决了用户输入和打印的问题，现在我们需要将输入的字符转换为 ASCII 码，并以十六进制或十进制格式输出。在完成这个任务之前，为了处理现在和未来的汇编代码，我们需要引入函数的概念，来构建一个统一的编程范式。

### 函数

由于代码变得更加复杂了，如果继续使用宏，不可避免地会导致使用时，忘记宏到底会如何修改寄存器的值。我们这里引入函数的原因是，函数有自己的调用约定，能够更好地管理寄存器的使用和保存状态，从而避免寄存器冲突的问题。

下面对比使用宏和使用函数的区别：

```asm
doscall macro dosno, funcno
    mov     ah, dosno
    mov     al, funcno
    int     21h
endm

; 输出以 '$' 结尾的字符串，DS:DX 指向字符串
; void puts(const char* str);
puts proc
    push    bp
    mov     bp, sp
    push    ax
    push    dx
    
    mov     dx, [bp + 4]   ; 获取字符串地址
    doscall 09h, 00h

    pop dx
    pop ax
    pop bp
    ret
puts endp


; 调用逻辑
mov ax, offset input
push ax
call puts
add sp, 2

; 为了调用 puts 逻辑，调用结束后仅 ax 寄存器受到了影响 
```

```asm
; 输出字符串
puts macro str
    lea     dx, offset str      ; DS:DX -> 字符串
    mov     ah, 09h             ; DOS 功能：输出字符
    int     21h
endm

; 调用逻辑
puts input

; 为了调用 puts 逻辑，调用结束后，dx、ah 寄存器都受到了影响
```

函数在编程语言的发展中，已经有了非常规范的调用规则（调用约定），它们定义了函数如何接收参数、返回值以及如何保存和恢复寄存器的状态。通过遵循这些规则，函数能够确保在调用过程中不会破坏调用者的寄存器状态，从而避免寄存器冲突的问题。

我们通常可以在体系结构的 ABI 文档中找到这些调用约定的详细说明。有了这些规则，我们可以保证在调用函数时，调用者的寄存器状态不会被破坏，从而实现更可靠和可维护的代码。


### cdecl 调用约定

在 x86 汇编中，`cdecl`（C Declaration）是一种常见的[函数调用约定](https://zh.wikipedia.org/wiki/X86%E8%B0%83%E7%94%A8%E7%BA%A6%E5%AE%9A)，可以参考 C 的[汇编结果](https://godbolt.org/z/7eee8aKc1)，主要特点包括：
- 参数从右到左压入堆栈
- 调用者负责清理堆栈
- 返回值通过 `AX` 寄存器传递
- 支持可变参数

下面是一个简单的例子，展示了如何使用 `cdecl` 调用约定来实现一个加法函数：

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    add(1, 2);
}
```

汇编的结果如下：

```asm
_a$ = 8                                       ; size = 4
_b$ = 12                                      ; size = 4
_add    PROC
    push    ebp
    mov     ebp, esp
    mov     eax, DWORD PTR _a$[ebp]
    add     eax, DWORD PTR _b$[ebp]
    pop     ebp
    ret     0
_add    ENDP

_main   PROC
    push    ebp
    mov     ebp, esp
    push    2
    push    1
    call    _add
    add     esp, 8
    xor     eax, eax
    pop     ebp
    ret     0
_main   ENDP
```

#### 调用者视角

在上面的例子中，`main` 函数作为调用者，首先将 `b: 2` 压入栈中，然后将 `a: 1` 压入栈中，接着调用 `add` 函数。在调用结束后，`main` 函数负责清理栈空间，即通过 `add esp, 8` 来移除传递的参数。+8 是因为每个参数占用 4 个字节（32 位系统），总共有两个参数。不过我们的 8086 汇编实验环境是 16 位的，所以如果是两个参数的话，参数占用空间是 4 个字节（2 个字，每个字 2 字节）。 

#### 被调用者视角

从被调用者 `add` 函数的角度来看，它并不关心参数是如何传递的，只需要按照约定从堆栈中读取参数即可。`add` 函数通过 `ebp` 寄存器加上指定的偏移量来访问参数和局部变量，这是一种常见的做法，可以确保函数在调用时能够正确访问到所需的数据。

最终，`add` 函数将结果存储在 `eax` 寄存器中，并通过 `ret` 指令返回到调用者的控制流中。

#### 函数调用的栈内存模型

最后，我们来看一下函数调用时栈内存的布局：

```
内存高地址
┌----------------------┐
│  调用者的栈帧/参数区  │
│                      │
├----------------------┤  <-- 调用者 ebp（老的 ebp）
│  参数 2  (b)         │  [ebp+12]
├----------------------┤
│  参数 1  (a)         │  [ebp+8]
├----------------------┤
│  返回地址 (EIP)      │  [ebp+4]  ← call 指令压入
├----------------------┤  <-- 当前 ebp（新 ebp）
│  保存的旧 ebp        │  push ebp
├---------------------┤
│  局部变量 tmp        │  [ebp-4]  （sub esp,4 分配）
│  ...                 │  [ebp-8]  如有更多局部变量
│                      │
└----------------------┘
内存低地址
```

#### 函数调用辅助宏

实话实话，虽然函数调用解决了寄存器冲突的问题，但是每次写函数调用的很不爽，又要写 `push`、`call`、`add sp, xx`，和我们平时在 C 语言中调用函数的感觉差太多了。所以我们可以定义一些辅助宏，来简化函数调用的过程：

```asm
; 8086 兼容，仅可用于立即数和单个寄存器参数
; 函数调用宏，模拟 cdecl 调用约定
; INVOKE_C function, <arg[n], arg<n-1>, ..., arg2, arg1>
INVOKE_C macro function:req, args:vararg
    local argc, arg
    argc = 0

    ; 先数参数个数，便于后面清栈
    for arg, <args>
        argc = argc + 1
    endm

    ; 从左到右压参
    for arg, <args>
        ifidni <arg>, <ax>
            push ax
        else
            mov ax, arg
            push ax
        endif
    endm

    call function

    ; 调用者清栈（cdecl 风格）
    if argc gt 0
        add  sp, argc*2           ; 16 位下每参数 2 字节
    endif
endm
```

对了，这里有几个注意事项：

1. 这个宏是**从左到右**进行参数压栈的，而我们需要的是**从右到左**压栈，所以在使用时需要注意参数的顺序。
2. 由于 8086 汇编的限制，无法 `push` 立即数（80186 及以后的处理器支持），所以就导致了这个宏只能处理立即数**或**单个寄存器作为参数，不能处理立即数和寄存器混合的情况。


### 打印一个数字

先考虑最小的问题，假设我们已经有一个数字在 `AX` 寄存器中，我们需要将它打印出来，比如 `ax = 9` 需要打印字符 `9`，`ax = 10` 需要打印字符 `A`。我们可以通过以下步骤实现：

![](/assets/images/blog/microcomputer-2/flowgraph.png)


将这四个基本块组合起来，写成汇编代码，我们就可以实现打印数字的功能了，完整代码如下：

```asm
; 打印 0-9 A-F 的数字
; void putnum(const char num);
putnum proc
@@entry:
    push    bp
    mov     bp, sp
    push    ax

    mov     al, [bp + 4]        ; 获取参数 num
    cmp     al, 9
    jbe     @@print_num

    ; 16 进制 A-F
@@print_alpha:
    add     al, 'A' - 10
    jmp     @@exit

    ; 10 进制 0-9
@@print_num:
    add     al, '0'
    jmp     @@exit

@@exit:
    INVOKE_C putc, <ax>         ; 输出字符
    pop     ax
    pop     bp
    ret
putnum endp

; 测试代码
INVOKE_C putnum, 08h
INVOKE_C putnum, 09h
INVOKE_C putnum, 0Ah
INVOKE_C putnum, 0Ch
```

### 打印 ascii 码

现在，我们可以使用上面的 `putnum` 函数来打印 0-9 A-F 的数字了。接下来，我们需要将输入的字符根据指定的进制进行打印。基本思路就是，不断地将数字除以进制，然后将余数保存下来，最后逆序输出这些余数。完整代码如下：

```asm
; 需要输出的 ascii 码，assert(radix > 1)
; void print(const char ascii, const char radix);
print proc
    push    bp
    mov     bp, sp
    push    ax
    push    bx
    sub     sp, 4

    ; char data[4]              ; 保存余数的数组
    mov     si, 0               ; 数组索引

    ; ax = ascii. bx = radix
    mov     ax, [bp + 4]        ; 设置被除数
    xor     ah, ah              ; 清除高位以防干扰
    mov     bx, [bp + 6]        ; 设置除数
    xor     bh, bh              ; 清除高位以防干扰


    ; 循环除以 <radix>，直到商为 0
@@while_1:
    div     bl                  ; 除以 <radix>，商在 AL，余数在 AH

    ; 余数保存到局部变量
    mov     [bp + si - 4], ah   ; data[si] = AH
    xor     ah, ah              ; 清除高位以防干扰
    inc     si                  ; 索引加 1

    cmp     al, 0
    jne     @@while_1

    ; 逆序输出保存的余数
@@while_2:
    dec     si
    mov     al, [bp + si - 4]     ; 取出 data[si]
    INVOKE_C putnum, <ax>
    cmp     si, 0
    jne     @@while_2

    ; 恢复栈
    add     sp, 4
    pop     bx
    pop     ax
    mov     sp, bp
    pop     bp
    ret
print endp

; 测试代码
; 请勿使用 INVOKE_C 宏来调用 print 函数，因为参数较多，会导致 ax 寄存器被覆盖

; 测试 10 进制打印
push 10
mov ax, 'A'
call print
add sp, 2

; 测试 16 进制打印
push 16
mov ax, 'A'
call print
add sp, 2
```

### Q&A 环节

Q: 怎么写好一个循环呢？

A: 写循环的关键在于正确设置循环的起始条件、终止条件以及循环体内的逻辑。一般来说，会使用标签（Label）来标记循环的开始和结束位置，然后使用条件跳转指令（如 `JE`、`JNE`、`JL`、`JG` 等）来控制循环的执行流程。可以速查一下[指令集](https://zhuanlan.zhihu.com/p/53394807)。

Q: `div` 指令是怎么工作的？

A: `div` 指令用于无符号除法操作。在 16 位模式下，`div` 指令将 `AX` 寄存器中的值作为被除数，除以指定的操作数（通常是一个寄存器或内存位置）。结果的商存储在 `AL` 寄存器中，余数存储在 `AH` 寄存器中。例如，如果 `AX` 中的值是 25，除数是 4，那么执行 `div` 后，`AL` 将包含商 6，`AH` 将包含余数 1。它还有一个亲戚 `idiv`，用于有符号除法。

Q: 如何在函数中定义局部变量？

A: 众所周知，局部变量是分配在栈上面的，所以我们可以通过调整栈指针 `SP` 来为局部变量分配空间。通常在函数开始时，我们会通过 `SUB SP, n` 来为局部变量分配 `n` 字节的空间，然后通过基址指针 `BP` 来访问这些局部变量。例如，如果我们需要一个 4 字节的局部变量，可以这样做：
```asm
push    bp
mov     bp, sp
sub     sp, 4               ; 为局部变量分配 4 字节
mov     [bp - 4], ax        ; 将 AX 的值存储到局部变量
```
当然，请始终记得你的局部变量所在的偏移量。

## 完整代码

我们将上面的代码整合在一起，形成完整的实验代码：

```asm
.model small
.stack 100h

.data
crlf    db      13, 10, '$'
msg     db      'Hello World!' ,'$'
bye     db      'GoodBye!' ,'$'
sname   db      'sname: ' ,'$'
sno     db      'sno: ' ,'$'
prompt  db      'Input a char: $'
n_hex   db      'Hex: $'
n_dec   db      'Dec: $'

; 为用户输入分配内存
name_input db 20          ; byte 0: 最大输入长度
           db ?           ; byte 1: 实际输入长度
           db 20 dup(0)   ; byte 3: 输入缓冲区

sno_input  db 20          
           db ?           
           db 20 dup(0)   

.code

; 一般来说，我们会把常用的系统调用封装成函数，放在一个单独的文件里，方便复用
; 但是这里为了展示全部的代码，我们直接把它完整带过来了
; include common.asm

; DOS 中断调用宏
doscall macro dosno, funcno
    mov     ah, dosno
    mov     al, funcno
    int     21h
endm

; 获取一个字符到 AL
; char getc();
getc proc
    push    bp
    mov     bp, sp
    sub     sp, 1           ; 给 AH 留 1 字节
    mov     [bp - 2], ah    ; 保存 AH 

    doscall 01h, 00h

    ; 恢复栈空间
    mov     ah, [bp - 2]
    mov     sp, bp
    pop     bp
    ret
getc endp

; 输出一个字符
; void putc(const char ch);
putc proc
    push    bp
    mov     bp, sp
    push    ax
    push    dx

    ; 从栈中获取用户输入的字符
    ; 2 个字节的返回地址 + 2 个字节的参数
    mov     dl, [bp + 4]
    doscall 02h, 00h

    pop     dx
    pop     ax
    pop     bp
    ret
putc endp

; 输出以 '$' 结尾的字符串，DS:DX 指向字符串
; void puts(const char* str);
puts proc
    push    bp
    mov     bp, sp
    push    ax
    push    dx
    
    mov     dx, [bp + 4]   ; 获取字符串地址
    doscall 09h, 00h

    pop dx
    pop ax
    pop bp
    ret
puts endp

; 获取用户输入的字符串，DS:DX 指向输入缓冲区
; void gets(char* buf);
gets proc
    push    bp
    mov     bp, sp
    push    ax

    mov     dx, [bp + 4]   ; 获取输入缓冲区地址
    doscall 0Ah, 00h

    pop ax
    pop bp
    ret
gets endp

; 8086 兼容，仅可用于立即数和单个寄存器参数
; 函数调用宏，模拟 cdecl 调用约定
; INVOKE_C function, <arg[n], arg<n-1>, ..., arg2, arg1>
INVOKE_C macro function:req, args:vararg
    local argc, arg
    argc = 0

    ; 先数参数个数，便于后面清栈
    for arg, <args>
        argc = argc + 1
    endm

    ; 从左到右压参
    for arg, <args>
        ifidni <arg>, <ax>
            push ax
        else
            mov ax, arg
            push ax
        endif
    endm

    call function

    ; 调用者清栈（cdecl 风格）
    if argc gt 0
        add  sp, argc*2           ; 16 位下每参数 2 字节
    endif
endm

; 为用户输入的结尾添加 $
pushend macro buffer
    mov     cl, buffer+1            ; CL = 用户输入的字符数
    mov     ch, 0                   ; CX = 长度
    lea     si, buffer+2            ; SI 指向第一个字符
    add     si, cx                  ; SI 跳过 CX 个字符
    mov     byte ptr [si], '$'      ; 把 '$' 放在最后一个字符之后
endm

; 打印 0-9 A-F 的数字
; void putnum(const char num);
putnum proc
    push    bp
    mov     bp, sp
    push    ax

    mov     al, [bp + 4]        ; 获取参数 num
    cmp     al, 9
    jbe     @@print_num

    ; 16 进制 A-F
@@print_alpha:
    add     al, 'A' - 10
    jmp     @@exit

    ; 10 进制 0-9
@@print_num:
    add     al, '0'
    jmp     @@exit

@@exit:
    INVOKE_C putc, <ax>         ; 输出字符
    pop     ax
    pop     bp
    ret
putnum endp

; 需要输出的 ascii 码
; assert(radix > 1)
; void print(const char ascii, const char radix);
print proc
    push    bp
    mov     bp, sp
    push    ax
    push    bx
    sub     sp, 4  

    ; char data[4]              ; 保存余数的数组
    mov     si, 0               ; 数组索引

    ; ax = ascii. bx = radix
    mov     ax, [bp + 4]        ; 设置被除数
    xor     ah, ah              ; 清除高位以防干扰
    mov     bx, [bp + 6]        ; 设置除数
    xor     bh, bh              ; 清除高位以防干扰


    ; 循环除以 <radix>，直到商为 0
@@while_1:
    div     bl                  ; 除以 <radix>，商在 AL，余数在 AH

    ; 余数保存到局部变量
    mov     [bp + si - 4], ah   ; data[si] = AH
    xor     ah, ah              ; 清除高位以防干扰
    inc     si                  ; 索引加 1

    cmp     al, 0
    jne     @@while_1

    ; 逆序输出保存的余数
@@while_2:
    dec     si
    mov     al, [bp + si - 4]     ; 取出 data[si]
    INVOKE_C putnum, <ax>
    cmp     si, 0
    jne     @@while_2

    ; 恢复栈
    add     sp, 4
    pop     bx
    pop     ax
    mov     sp, bp
    pop     bp
    ret
print endp

main proc
    ; 初始化数据段和栈指针
    mov     ax, @data
    mov     ds, ax

    ; 题目 1：输出 "Hello World!"
@@topic_1:
    INVOKE_C puts, <offset msg>
    INVOKE_C puts, <offset crlf>

    ; 题目 2：获取用户输入并输出
@@topic_2:
    ; 2.1 获取用户输入的 name
    INVOKE_C puts, <offset sname>
    INVOKE_C gets, <offset name_input>
    pushend name_input
    INVOKE_C puts, <offset crlf>

    ; 2.2 获取用户输入的 sno
    INVOKE_C puts, <offset sno>
    INVOKE_C gets, <offset sno_input>
    pushend sno_input
    INVOKE_C puts, <offset crlf>

    ; 2.3 回显 name 和 sno
    INVOKE_C puts, <offset name_input+2>
    INVOKE_C puts, <offset crlf>
    INVOKE_C puts, <offset sno_input+2>
    INVOKE_C puts, <offset crlf>

    ; 题目 3：输入一个字符，输出其 ASCII 码的十六进制和十进制表示
@@topic_3:
    ; 3.1 提示用户输入一个字符
    INVOKE_C puts, <offset prompt>
    INVOKE_C getc
    INVOKE_C puts, <offset crlf>

    ; 3.2 检查是否为 'q' 或 'Q'，是则结束程序
    cmp al, 'q'
    je @@end
    cmp al, 'Q'
    je @@end

    ; 3.3 输出该字符的 ASCII 码的十六进制和十进制表示
    INVOKE_C puts, <offset n_hex>
    
    push 16
    push ax
    call print
    add sp, 4

    INVOKE_C puts, <offset crlf>
    
    INVOKE_C puts, <offset n_dec>

    push 10
    push ax
    call print
    add sp, 4

    INVOKE_C puts, <offset crlf>
    jmp @@topic_3

@@end: 
    INVOKE_C puts, <offset bye>
    ; 带返回码 0 结束
    mov     ah, 4Ch         
    xor     al, al
    int     21h

main endp
end main
```
