## 前言

这篇是西电计科专业微机原理随课实验的第二篇文章，主要介绍使用 MASM 的 x86 汇编。首先需要警告一下，本文所涉及的内容比较深入原理，大部分和直接写完实验代码关系不大，如果你只是想完成实验任务，而不是想要深入汇编的话，那么可以忽略本文，直接看之后实验代码的部分。

## MASM 汇编简介

MASM（Microsoft Macro Assembler）是微软公司开发的一款 x86 汇编语言编译器，广泛应用于 Windows 平台的软件开发中。它支持多种汇编语言指令集，能够生成高效的机器代码。MASM 提供了丰富的宏功能和高级语法，使得编写汇编代码更加方便和灵活。一般提起汇编器，还有另一个在 Linux 下使用的 GNU 汇编器（GAS），两者在语法上有较大差异，本文主要介绍 MASM 的语法和使用方法。

## x86 汇编基础

x86 汇编语言是一种低级编程语言，直接与计算机的硬件进行交互。我们的计算机只能看到固定序列的 `01` 组成的机器码，而汇编语言则是对这些机器码的一种更易读的表示形式。它使用助记符（汇编指令）来表示机器指令，使得程序员能够更容易地编写和理解代码。换句话说，**汇编就是机器码的别名**。

和我们平时写的高级语言（如 C、C++、Python 等）相比，汇编语言最大的特点就是平面化，没有函数、类等高级结构，只有一条条顺序执行的指令。程序员需要手动管理内存、寄存器等底层资源，这使得汇编语言具有极高的灵活性和效率，但也增加了编程的复杂度。

### 寄存器

寄存器是 CPU 内部用于存储数据的高速存储单元。在 16 bit 的 x86 架构中，常用的寄存器包括：
- AX（累加寄存器）：用于算术运算和数据传输。
- BX（基址寄存器）：通常用于存储数据的地址。
- CX（计数寄存器）：用于循环和字符串操作的计数。
- DX（数据寄存器）：用于输入输出操作和算术运算。
- SP（堆栈指针寄存器）：指向当前堆栈的顶部。
- BP（基指针寄存器）：用于访问堆栈中的参数和局部变量。
- SI（源变址寄存器）：用于字符串操作的源地址。
- DI（目的变址寄存器）：用于字符串操作的目的地址。
- IP（指令指针寄存器）：指向下一条要执行的指令。

### 段寄存器
x86 架构采用分段存储模式，内存被划分为多个段，每个段都有一个段寄存器来指示当前使用的段。常用的段寄存器包括：
- CS（代码段寄存器）：指向当前执行的代码段。
- DS（数据段寄存器）：指向当前使用的数据段。
- SS（堆栈段寄存器）：指向当前使用的堆栈段。
- ES（附加段寄存器）：用于字符串操作的附加段。

## 控制流

控制流是指程序执行的顺序和路径。在 C 语言中，我们通过 `if` 语句、`for` 循环等结构来控制程序的执行流程。而在汇编语言中，只能通过跳转指令和条件指令来实现。

### 条件语句（IF）

在 C 语言中，我们描述条件语句通常是*如果满足某个条件，就执行某个操作*。而在汇编语言中，由于其平面化的特性，写条件时的思路恰好相反*如果满足某个条件，就不执行某个操作*，听起来很奇怪，看起来我们执行条件语句就是为了不执行某个操作。下面举一个例子来说明。

![](/assets/images/blog/microcomputer-2/cond-1.png)

```c
int a = 5;
int b = 10;

if (a >= b) {
    a ++;
}

return a+b;
```

同样的逻辑用汇编语言来实现：
```asm
    mov ax, 5      ; 将 5 赋值给寄存器 ax（变量 a）
    mov bx, 10     ; 将 10 赋值给寄存器 bx（变量 b）
    
    cmp ax, bx     ; 比较 ax 和 bx 的值
    jl  skip_inc   ; 如果 ax < bx，跳转到 skip_inc 标签（不执行 a++）    
    inc ax         ; 执行 a++（ax 加 1）

skip_inc:
    ; 继续执行其他代码
    add ax, bx     ; 计算 a + b 的值
    ; 返回结果在 ax 中
    ret
```

这个例子太简单了，现在我们来看一个稍微复杂一点的例子：

![](/assets/images/blog/microcomputer-2/cond-2.png)

```c
int a = 5;
int b = 10;
int c = 15;

if (a < b && b < c) {
    a++;
} else {
    a += 2;
}

return a + b + c;
```

这就比较复杂了，我们需要同时判断两个条件，并且有一个 else 分支。然而在汇编中，我们每一次只能判断一个条件，所以我们需要把这个复合条件拆开来处理。下面是对应的汇编代码：同样的逻辑用汇编语言来实现：

```asm
    mov ax, 5      ; 将 5 赋值给寄存器 ax（变量 a）
    mov bx, 10     ; 将 10 赋值给寄存器 bx（变量 b）
    mov cx, 15     ; 将 15 赋值给寄存器 cx（变量 c）
    
    cmp ax, bx     ; 比较 ax 和 bx 的值
    jge else_branch ; 如果 ax >= bx，跳转到 else_branch 标签（执行 else 分支）
    
    cmp bx, cx     ; 比较 bx 和 cx 的值
    jge else_branch ; 如果 bx >= cx，跳转到 else_branch 标签（执行 else 分支）
    
    inc ax         ; 执行 a++（ax 加 1）
    jmp end_if     ; 跳转到 end_if 标签，结束 if 语句
else_branch:
    add ax, 2      ; 执行 a += 2

end_if:
    ; 继续执行其他代码
    add ax, bx     ; 计算 a + b 的值
    add ax, cx     ; 计算 a + b + c 的值
    ; 返回结果在 ax 中
    ret
```

有了上面的例子，我们可以对更加复杂的条件语句进行拆解和实现了。

### 循环语句（LOOP）

循环语句用于重复执行一段代码，直到满足某个条件为止。在 C 语言中，我们通常使用 `for` 或 `while` 循环来实现。而在 x86 汇编语言中，我们依靠跳转指令和计数寄存器(CX)来实现循环。

下面是一个使用 `for` 循环的 C 语言示例：

```c
int sum = 0;
for (int i = 1; i <= 10; i++) sum += i;
```

我们在 x86 汇编中几乎不会遇到更复杂的循环结构，因为汇编语言本身就很底层了，程序员需要手动管理循环的每一个细节。下面就是上述 C 代码对应的汇编代码：

```asm
    mov cx, 10     ; 将循环计数器设置为 10
    mov ax, 0      ; 初始化 sum 为 0
    mov bx, 1      ; 初始化 i 为 1

    cmp cx, 0      ; 务必检查 cx 是否为 0，避免死循环
    je end_loop    ; 如果 cx 为 0，跳转到 end_loop 标签
loop_start:
    add ax, bx     ; sum += i
    inc bx         ; i++
    loop loop_start ; 循环直到 cx 为 0
end_loop:

    ; 返回结果在 ax 中
    ret
```

这里有一个需要注意的地方是，`loop` 指令会自动将 CX 寄存器减 1，并检查是否为 0，如果不为 0 就跳转到指定的标签。那如果我们的 CX 一开始就是 0 呢？
那么 `0-1 = FFFFh`，这就变成了一个非常大的数。所以在使用 `loop` 指令前，务必检查 CX 是否为 0，除非能够保证用户传入的值一定不为 0。

## masm 中的宏

什么是宏？在 C 里面我们经常会用 `#define` 来定义宏，`masm` 的汇编语言中的宏定义方式略有不同，但本质上都是一种预处理指令，用于在编译时进行文本替换。通过这种替换的机制，它们允许我们定义一段代码块，并在需要的地方插入这段代码，从而避免重复编写相同的代码，提高代码的可读性和维护性。

通常，我们会使用宏来封装一些常用的操作，比如打印字符串、读取输入等，然后写好文档，告诉使用者调用这个宏时需要传入哪些参数、会有什么副作用等。比如下面就是一个在 DOS 中打印字符串的宏：

```asm
; 打印字符串宏
; 参数：str - 指向要打印的字符串的指针
; 使用 DOS 中断 21h 的功能号 09h 来打印字符串
; 字符串必须以 '$' 结尾
puts macro str
    mov dx, str  ; 将字符串指针加载到 DX 寄存器
    mov ah, 09h  ; DOS 打印字符串功能号
    int 21h      ; 调用 DOS 中断
endm

; 示例使用
.data
message db 'Hello, World!$', 0
.code
start:
    puts <offset message>  ; 调用 puts 宏打印字符串
    
    mov ax, 4C00h ; 退出程序
    int 21h
end start
```

本质上，宏就是一种代码生成工具，上面的代码在编译时会被展开成下面的代码，也是是把传入的参数直接替换到宏定义中的位置，然后在原封不动地插入到调用宏的位置上：

```asm
.data
message db 'Hello, World!$', 0
.code
start:    
    mov dx, offset message
    mov ah, 09h
    int 21h
    
    mov ax, 4C00h
    int 21h
end start
```

这里仍旧有需要注意的地方，比如传参的问题。上面的宏调用时传入的是 `<offset message>`，而不是 `offset message`，这是因为 MASM 宏在处理参数时会把尖括号内的内容作为一个整体传递给宏定义，而不会对其进行进一步的解析。如果直接传入 `offset message`，那么 MASM 会将其拆分成两个参数 `offset` 和 `message`，导致宏展开时出错。

## masm 中的过程调用

过程调用（Procedure Call）是指在程序中调用一个独立的代码块，并在执行完毕后返回到原来的位置继续执行。这个概念可能比较陌生，因为在汇编语言大行其道的时候，在编程语言中还没有`函数`这个概念，当然函数也是过程调用的一种形式。可以看一下 C 语言是的函数对应的[汇编代码](https://godbolt.org/z/WPrGeWb8M)。

MASM 支持过程调用（Procedure Call），允许程序员将代码组织成独立的模块，每个模块完成特定的功能，可以通过 `CALL` 指令调用过程，通过 `RET` 指令返回。这个时候就会问了，过程调用和宏有什么区别呢？

核心区别在于，宏是在编译时展开的，而过程调用是在运行时执行的。也就是说，宏会将代码直接插入到调用位置，而过程调用则会跳转到过程的代码段执行，然后再返回。下面是一个简单的过程调用示例：

```asm
start:
    mov ax, 5
    mov bx, 10
    call add_numbers  ; 调用 add_numbers 过程
    call add_numbers  ; 调用 add_numbers 过程
    call add_numbers  ; 调用 add_numbers 过程
    ; 结果在 ax 中
    mov ax, 4C00h     ; 退出程序
    int 21h

add_numbers proc
    add ax, bx        ; 执行加法操作
    ret
add_numbers endp
```

在这个例子中，`add_numbers` 是一个过程，它接受两个参数（通过寄存器传递），执行加法操作，并将结果存储在 `AX` 寄存器中。调用过程时，程序会跳转到 `add_numbers` 过程的代码段执行，执行完毕后通过 `RET` 指令返回到调用位置继续执行。
我在上面的例子中多次调用了 `add_numbers` 过程，如果我使用宏来实现同样的功能，代码在展开后会变得非常冗长（复制粘贴 3 次），也就会影响编译后的二进制文件的大小和性能，但是使用过程调用则不会有这个问题，我们执行的始终是同一段代码。

## 进阶：cdecl 调用约定

当代码规模变大时，我们会遇到一些问题，我调用了一个过程/宏，这个过程/宏对我的寄存器进行了修改，导致我后续的代码出现了问题，如果我们需要关心每一个过程调用对寄存器的影响，那编写代码就会变得非常复杂，几乎无法维护。**没有一个程序员可以忍受这样黑暗的事情！**。

为了解决这个问题，我们需要一种规范，来约定过程调用时参数的传递方式、寄存器的使用规则等，这就是**调用约定**（Calling Convention）。

在 x86 汇编中，`cdecl`（C Declaration）是一种常见的[函数调用约定](https://zh.wikipedia.org/wiki/X86%E8%B0%83%E7%94%A8%E7%BA%A6%E5%AE%9A)，可以参考 C 的[汇编结果](https://godbolt.org/z/7eee8aKc1)，主要特点包括：
- 参数从右到左压入堆栈
- 调用者负责清理堆栈
- 返回值通过 `AX` 寄存器传递
- 支持可变参数

下面是一个简单的例子，展示了如何使用 `cdecl` 调用约定来实现一个加法函数：

```c
int add(int a, int b) {
    return a + b;
}

int main() {
    add(1, 2);
}
```

汇编的结果如下：

```asm
_a$ = 8                                       ; size = 4
_b$ = 12                                      ; size = 4
_add    PROC
    push    ebp
    mov     ebp, esp
    mov     eax, DWORD PTR _a$[ebp]
    add     eax, DWORD PTR _b$[ebp]
    pop     ebp
    ret     0
_add    ENDP

_main   PROC
    push    ebp
    mov     ebp, esp
    push    2
    push    1
    call    _add
    add     esp, 8
    xor     eax, eax
    pop     ebp
    ret     0
_main   ENDP
```

### 调用者视角

在上面的例子中，`main` 函数作为调用者，首先将 `b: 2` 压入栈中，然后将 `a: 1` 压入栈中，接着调用 `add` 函数。在调用结束后，`main` 函数负责清理栈空间，即通过 `add esp, 8` 来移除传递的参数。+8 是因为每个参数占用 4 个字节（32 位系统），总共有两个参数。不过我们的 8086 汇编实验环境是 16 位的，所以如果是两个参数的话，参数占用空间是 4 个字节（2 个字，每个字 2 字节）。 

### 被调用者视角

从被调用者 `add` 函数的角度来看，它并不关心参数是如何传递的，只需要按照约定从堆栈中读取参数即可。`add` 函数通过 `ebp` 寄存器加上指定的偏移量来访问参数和局部变量，这是一种常见的做法，可以确保函数在调用时能够正确访问到所需的数据。

最终，`add` 函数将结果存储在 `eax` 寄存器中，并通过 `ret` 指令返回到调用者的控制流中。

### 函数调用的栈内存模型

最后，我们来看一下函数调用时栈内存的布局：

```
内存高地址
┌----------------------┐
│  调用者的栈帧/参数区  │
│                      │
├----------------------┤  <-- 调用者 ebp（老的 ebp）
│  参数 2  (b)         │  [ebp+12]
├----------------------┤
│  参数 1  (a)         │  [ebp+8]
├----------------------┤
│  返回地址 (EIP)      │  [ebp+4]  ← call 指令压入
├----------------------┤  <-- 当前 ebp（新 ebp）
│  保存的旧 ebp        │  push ebp
├----------------------┤  
|  寄存器保存区 n 块    │  如有需要保存的寄存器
├---------------------┤
│  局部变量 tmp        │  [ebp-4 - 4*n]  （sub esp,4 分配）
│  ...                 │  [ebp-8 - 4*n]  如有更多局部变量
│                      │
└----------------------┘
内存低地址
```

### 函数调用辅助宏

实话实话，虽然函数调用解决了寄存器冲突的问题，但是每次写函数调用的很不爽，又要写 `push`、`call`、`add sp, xx`，和我们平时在 C 语言中调用函数的感觉差太多了。所以我们可以定义一些辅助宏，来简化函数调用的过程：

```asm
; 8086 兼容，仅可用于立即数和单个寄存器参数
; 函数调用宏，模拟 cdecl 调用约定
; INVOKE_C function, <arg[n], arg<n-1>, ..., arg2, arg1>
INVOKE_C macro function:req, args:vararg
    local argc, arg
    argc = 0

    ; 先数参数个数，便于后面清栈
    for arg, <args>
        argc = argc + 1
    endm

    ; 从左到右压参
    for arg, <args>
        ifidni <arg>, <ax>
            push ax
        else
            mov ax, arg
            push ax
        endif
    endm

    call function

    ; 调用者清栈（cdecl 风格）
    if argc gt 0
        add  sp, argc*2           ; 16 位下每参数 2 字节
    endif
endm


; 仅 8086 以上支持
; 记得开启 .286
; 函数调用宏，模拟 cdecl 调用约定
; INVOKE_C function, <arg[n], arg<n-1>, ..., arg2, arg1>
INVOKE_C macro function:req, args:vararg
    local argc, arg
    argc = 0

    ; 先数参数个数，便于后面清栈
    for arg, <args>
        argc = argc + 1
    endm

    ; 从左到右压参
    for arg, <args>
        push arg
    endm

    call function

    ; 调用者清栈（cdecl 风格）
    if argc gt 0
        add  sp, argc*2           ; 16 位下每参数 2 字节
    endif
endm
```

对了，这里有几个注意事项：

1. 这个宏是**从左到右**进行参数压栈的，而我们需要的是**从右到左**压栈，所以在使用时需要注意参数的顺序。
2. 由于 8086 汇编的限制，无法 `push` 立即数（80186 及以后的处理器支持），所以就导致了这个宏只能处理立即数**或**单个寄存器作为参数，不能处理立即数和寄存器混合的情况。
