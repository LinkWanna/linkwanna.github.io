## 术语解读

### 微指令

我们课设的 CPU 是 CISC 架构，需要设计一套微指令集，微指令的本质就是对 CPU 内部操作的细粒度控制，微指令中的每一个字段都可以在 CPU 的设计中找到对应的管脚定义。

多个微指令可以组合成复杂的操作，比如 x86 指令集中的 `MOV` 指令，可能需要多个微指令来完成数据的读取、写入和寄存器的更新，主要还是因为同一时刻总线上只能有一个输出信号。（采用哈佛架构的指令集就有效避免了这种使用微指令的尴尬局面）

落到我们的课设上，我们需要读懂微指令中的每一个字段定义，然后根据这些字段的含义来设计微指令的实现，也就是修改 ROM 中的数据。

## 寄存器声明

在课设的 CPU 设计中，提供了一个 8 个寄存器：
- **PC**: 程序计数器（Program Counter），指向下一条指令的地址（执行 RAM 中）
- **AR**：地址寄存器（Address Register），存放当前指令的地址
- **IR**：指令寄存器（Instruction Register），存放当前指令的内容
- **R0, R1, R2**：通用寄存器（General Purpose Registers），用于存放临时数据
- **DR1, DR2**：数据寄存器（Data Registers），用于在总线和 ALU 之间缓冲数据 

在文档中，还可以看到很多对寄存器的操作信号，文档中并没有对其进行标识：
1. **LD**：加载信号，将数据从总线加载到指定寄存器中（bus -> reg），例如 `LDDR1`，将数据从总线加载到寄存器 R1 中。
2. **xxx-B**：输出信号，将指定寄存器的数据输出到总线（reg -> bus），例如 `RD-B`，将目标寄存器（具体是哪一个通用寄存器取决于操作码 (opcode) 中的 `rd` 字段）的数据输出到总线。

## 微指令文档解读

这部分是出了名的模糊，文档压根就没有说清楚每一个字段的语义。

![](/assets/images/blog/architecture-design-1/micro_inst.png)

这里尝试重新整理了一遍。

1. **uA[5\:0]**: 下一条要执行的微指令的微地址。
    - 这个字段的值决定了微指令的执行顺序。
    - 微地址指向 ROM 中的某个位置，那里存放下一条需要执行的微指令。

2. **C 字段**：
 
| C[2] | C[1] | C[0] | 含义|
|---|---|---|-----------|
| 0 | 0 | 0 | 无操作   |
| 0 | 0 | 1 | P(1)   |
| 0 | 1 | 0 | P(2)：无效操作   |
| 0 | 1 | 1 | P(3)：无效操作   |
| 1 | 0 | 0 | P(4)   |
| 1 | 0 | 1 | LDAR：Bus -> AR     |
| 1 | 1 | 0 | LDPC：Bus -> PC    |

3. **B 字段**：B 字段决定了哪一个信号会输出到总线上

| B[2] | B[1] | B[0] | 含义  |
|---|---|---|-----------|
| 0 | 0 | 0 | 无操作         |
| 0 | 0 | 1 | RS-B：RS -> Bus      |
| 0 | 1 | 0 | RD-B：RD -> Bus      |
| 0 | 1 | 1 | RJ-B：RJ -> Bus      |
| 1 | 0 | 0 | SFT-B：SFT -> Bus     |
| 1 | 0 | 1 | ALU-B：ALU -> Bus     |
| 1 | 1 | 0 | PC-B：PC -> Bus      |


> 你可以发现有一些操作在文档上其实是留空的呢，因为这是我根据 cpu 设计中的各个字段自己扣出来的呀！天哪，老师居然让我们在文档上做填空题！！！


4. **A 字段**：A 字段决定了哪个寄存器会接收总线上的数据

| A[2] | A[1] | A[0] | 含义  |
|---|---|---|-----------|
| 0 | 0 | 0 | 无操作         |
| 0 | 0 | 1 | Bus -> Ri      |
| 0 | 1 | 0 | Bus -> DR1      |
| 0 | 1 | 1 | Bus -> DR2      |
| 1 | 0 | 0 | Bus -> AR      |
| 1 | 0 | 1 | Bus -> PC      |
| 1 | 1 | 0 | Bus -> IR      |


> **`Ri` 指的是什么？**<br>
RI 来自与 opcode 中的 `rd` 字段：**00：无操作**，**01：R0**，**10：R1**，**11：R2**。
